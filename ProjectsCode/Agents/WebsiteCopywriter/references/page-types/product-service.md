# Product & Service Page Copy Guide

Product and service pages are where features meet benefits. These pages must communicate what you offer, why it matters, and move visitors toward conversion.

---

## Page Purpose

**Primary goals:**
1. Clearly explain what the product/service does
2. Communicate benefits, not just features
3. Address objections and concerns
4. Provide enough detail for decision-making
5. Convert interest into action (trial, buy, contact)

---

## Product Page Structure

### Recommended Sections

1. **Hero** - Product name, positioning, primary benefit
2. **Key Benefits** - Top 3-5 reasons to care
3. **Feature Details** - Comprehensive feature breakdown
4. **How It Works** - Process or workflow
5. **Use Cases** - Who uses it and how
6. **Social Proof** - Product-specific testimonials
7. **Specifications** - Technical details (if applicable)
8. **Pricing/CTA** - Clear next step
9. **FAQ** - Product-specific questions
10. **Related Products** - Cross-sell opportunities

---

## Hero Section

### Elements

| Element | Purpose |
|---------|---------|
| Product name | Clear identification |
| Category descriptor | What type of product is this |
| Primary benefit | Main reason to use it |
| Visual | Product screenshot, image, or demo |
| CTA | Primary action (try, buy, demo) |

### Positioning Statement Formula

`[Product] is a [category] that helps [audience] [achieve outcome] [unlike/without competitor problem].`

**Example:**
"TaskFlow is a project management platform that helps remote teams ship faster without endless meetings."

---

## Benefits vs. Features

### The Difference

| Feature | Benefit |
|---------|---------|
| What it does | Why it matters |
| Technical capability | User outcome |
| Specification | Value to customer |

### Translating Features to Benefits

**Formula:** [Feature] so you can [Benefit].

| Feature | Benefit |
|---------|---------|
| AI-powered recommendations | Discover exactly what you need, faster |
| Real-time sync | Never work with outdated information |
| One-click integrations | Connect your tools in minutes, not days |
| 256-bit encryption | Your data stays safe, always |
| 24/7 support | Get help whenever you need it |

### Benefit Writing Tips

- Focus on outcomes, not mechanics
- Use "you" language
- Be specific, not generic
- Address pain points they recognize
- Include quantified benefits when possible

## Feature Sections

### Feature Presentation Options

**Icon + headline + description:**
```
🔄 Real-Time Sync
All team members see updates instantly. No more "did you see my changes?" conversations.
```

**Feature tabs:**
- Tab 1: Feature category
- Tab 2: Feature category
- Each tab expands with detail

**Feature deep-dive blocks:**
- Screenshot/visual
- Feature headline
- 2-3 benefit bullets
- Brief description

### Feature Hierarchy

Order features by:
1. Most valued/differentiating
2. Most commonly sought
3. Most impressive for social proof

### Feature Copy Format

```markdown
## [Feature Name]

**What it does:**
[One sentence explanation]

**Why it matters:**
[Benefit framing - how this helps the user]

**How it works:**
[Brief process or mechanism]

**Example:**
[Real use case or scenario]
```

## How It Works Section

### Purpose

Reduce complexity anxiety. Show the process is simple, even if the product is sophisticated.

### Standard Format

**3-step process:**
1. [Action] - [Brief description]
2. [Action] - [Brief description]
3. [Action] - [Brief description]

**Example:**
1. **Connect** - Link your existing tools in one click
2. **Configure** - Set up workflows with our drag-and-drop builder
3. **Collaborate** - Your team starts working smarter immediately

### Tips

- Keep to 3-5 steps (fewer is better)
- Use active verbs for step names
- Include time estimates if impressive ("Set up in 5 minutes")
- Show visual for each step if possible

---

## Use Cases Section

### Purpose

Help visitors see themselves using the product. Demonstrate versatility or target specific segments.

### Format Options

**By persona:**
- "For Marketing Teams: [use case]"
- "For Sales Teams: [use case]"
- "For Operations: [use case]"

**By scenario:**
- "When you need to [situation]"
- "Perfect for [specific use]"

**By outcome:**
- "Track project progress in real-time"
- "Automate your reporting workflow"

### Use Case Copy Format

```markdown
### For [Persona/Scenario]

**The challenge:**
[Problem they face]

**The solution:**
[How the product helps]

**The result:**
[Outcome they achieve]
```

## Social Proof on Product Pages

### Types Most Effective

**Testimonials:**
- Product-specific quotes
- Results-focused
- From identifiable customers

**Case study teasers:**
- "[Customer] achieved [result] with [Product]"
- Link to full case study

**Usage stats:**
- "[X] teams use this feature daily"
- "[X]% of users report [outcome]"

**Review aggregation:**
- G2/Capterra ratings
- App store reviews

### Placement

- After features (reinforces claims)
- Near pricing/CTA (reduces final objection)
- Throughout (embedded with relevant features)

## Specifications Section

### When to Include

- Technical products requiring specs
- Physical products with dimensions/materials
- Compliance or security-focused buyers
- Comparison shoppers needing details

### What to Include

**SaaS/Software:**
- Supported platforms/browsers
- Integration list
- API availability
- Security certifications
- Uptime SLA
- Data residency options

**Physical products:**
- Dimensions and weight
- Materials
- Color options
- Technical specifications
- Warranty information

### Format

Tables work well for specifications:
```
| Specification | Details |
|--------------|---------|
| Supported browsers | Chrome, Firefox, Safari, Edge |
| Mobile apps | iOS 14+, Android 10+ |
| Integrations | Slack, Salesforce, Zapier, 50+ more |
| Security | SOC 2 Type II, GDPR compliant |
```

## Product Page CTA Strategy

### Primary CTA Options

| Stage | CTA |
|-------|-----|
| Free trial | "Start Free Trial" |
| Freemium | "Get Started Free" |
| Demo | "Request Demo" |
| Direct purchase | "Buy Now" |
| Contact | "Talk to Sales" |

### CTA Placement

- Hero section (above fold)
- After feature sections
- After social proof
- Sticky header/footer on long pages
- Page end

### Supporting CTAs

- "Watch Demo" (lower commitment)
- "See Pricing" (consideration stage)
- "Download Datasheet" (enterprise buyers)
- "Compare Plans" (multiple options)

## Product Page FAQ

### Common Questions to Address

**About the product:**
- How is this different from [competitor/alternative]?
- Does it integrate with [popular tool]?
- Is there a mobile app?
- Can I import my existing data?

**About implementation:**
- How long does setup take?
- Do I need technical knowledge?
- Is there a learning curve?
- What support is available?

**About suitability:**
- Is this right for [my situation]?
- What if I outgrow it?
- Can teams use this?

## Service Page Variations

### Structure for Service Pages

1. **Hero** - Service name, who it's for, primary benefit
2. **What We Do** - Service description
3. **Our Process** - How we work
4. **What You Get** - Deliverables
5. **Who It's For** - Ideal client
6. **Results** - Case studies, testimonials
7. **Pricing** (if applicable) - Or "Get a Quote"
8. **FAQ** - Common questions
9. **CTA** - Contact or book consultation

### Service Description Copy

**Include:**
- What the service is
- Who it's for
- What problems it solves
- What's included
- What results to expect

### Process Section for Services

```
## How We Work

### 1. Discovery
We start by understanding your business, goals, and challenges.

### 2. Strategy
We develop a custom plan tailored to your specific needs.

### 3. Execution
Our team implements the strategy with regular updates.

### 4. Results
We measure success and optimize for continued improvement.
```

## Common Product Page Mistakes

1. **Feature list without benefits:** Lists specs but doesn't explain value
2. **No process clarity:** Visitor doesn't know what happens next
3. **Missing use cases:** Can't see how it applies to them
4. **Weak social proof:** No testimonials or generic quotes
5. **Unclear CTA:** Multiple competing actions or vague CTA
6. **Too much jargon:** Technical language for non-technical audience
7. **No FAQ:** Missed objection handling opportunity
8. **Buried differentiators:** What makes you unique isn't prominent
9. **Ignoring competitors:** Not addressing comparison questions
10. **One-size-fits-all:** Not speaking to different personas/needs
